# WRITING-STYLE.md

実家のしらべ の記事執筆スタイルガイド。

CLAUDE.md セクション3.3「文体・トーン」を補完する詳細版。
**AIが書いたと判別されない自然な日本語**で書くための実践ルールを集約する。

このドキュメントは [CLAUDE.md](../CLAUDE.md) の補助文書。
矛盾があった場合は CLAUDE.md が優先される。

---

## 1. このドキュメントの目的

### 1.1 解決したい課題

GoogleのE-E-A-Tガイドラインでは、AI生成コンテンツそのものは禁止されていない。
ただし「**読者の役に立たない、機械的な、品質の低いAIコンテンツ**」は明確にペナルティ対象。

YMYL領域(介護・相続・終活)では特に厳しく評価されるため、以下を両立する必要がある:

- CLAUDE.md の制約を守る(体験談を語らない、断定を避ける、公的資料ベース)
- それでいて**AI臭さを消す**(均質な文体、機械的な接続詞、抽象的な結論を避ける)

### 1.2 AI記事と判別される主なシグナル

検出ポイント(GoogleもAIコンテンツ検出ツールも見ている指標):

1. 均質すぎる文体 — すべての段落が同じ長さ、同じ構造
2. 接続詞の偏り — 「また」「さらに」「つまり」「このように」が頻出
3. 抽象的すぎる表現 — 具体的な数字や固有名詞が少ない
4. 無難すぎる結論 — 「ケースバイケース」「個人差があります」で締める
5. 完璧すぎる構造 — 序論-本論-結論が綺麗すぎる
6. 温度感がない — 読者の状況や心情に寄り添う表現がない
7. 段落冒頭のパターン化 — すべての段落が「〇〇は〜です」で始まる

これらを避けつつ、CLAUDE.mdの方針を守る書き方を以下に整理する。

## 2. CLAUDE.mdの制約と本ガイドの関係

CLAUDE.md セクション1.4 で定められた絶対要件:

- ❌ 個人体験を語らない
- ❌ 断定表現(「絶対」「必ず」「確実に」)を使わない
- ❌ 個別具体的な金融・税務・法律助言をしない

これらは**変更しない**。本ガイドは、これらを守りつつ自然な文体を実現する方法を示す。

危険な「自然化」の例:

- ❌「私も親の介護で苦労しました」→ 体験談禁止に違反
- ❌「親の死は本当につらいですよね」→ 共感の押し付け、信頼性低下
- ❌「絶対に後悔しない選択を!」→ 断定表現禁止に違反

安全な「自然化」の例:

- ◯「親の介護は、多くのご家族にとって悩ましい問題です」
- ◯「介護のことは、なかなか家族で話し合いにくい話題でもあります」
- ◯「制度が複雑で戸惑う方も少なくありません」

**主語を「私」「あなた」ではなく「ご家族の方」「読者の方」「多くの方」に置き換える**ことで、共感を示しつつ体験談を回避できる。

## 3. 7つのコア技術

### 3.1 文長にリズムをつける

AIは均等な長さの文を生成しがち。人間の文章は短文・中文・長文が混ざる。

#### Before(AI臭い)

> 介護保険の申請には市区町村の窓口で行う必要があります。申請には介護保険被保険者証が必要です。申請後は認定調査が行われます。調査後に審査会で要介護度が決定されます。

#### After(自然)

> 介護保険の申請は、市区町村の窓口で行います。
>
> 必要なのは介護保険被保険者証(65歳の誕生日前後に郵送で届く水色のカード)。これを持って役所の介護保険課に行けば、申請書を渡されます。
>
> 申請後は認定調査員が自宅を訪問。本人と家族から生活の様子を聞き取り、その内容を元に審査会が要介護度を決めます。

ポイント:
- 文の長さがバラバラ(短文「必要なのは介護保険被保険者証」+ 中文 + 長文)
- 括弧での補足説明
- 体言止めの混在(「自宅を訪問。」)

### 3.2 「具体」を必ず1段下げる

AIは抽象的にまとめて満足する。**抽象的な記述には必ず具体を1段下げる**。

#### Before

> 介護費用は地域や介護度によって異なります。

#### After

> 介護費用は地域や介護度によって変わります。たとえば要介護3の方が特別養護老人ホームに入った場合、東京23区で月13万〜15万円、地方都市で月9万〜11万円が目安です(2025年度厚労省データ)。

ルール: 「異なる」で終わらせず、必ず**数字・地名・年度**のいずれかを足す。

### 3.3 整った接続詞を捨てる

AI臭さの最大の犯人は接続詞。

#### 避けるべき接続詞(AIが多用)

- 「また」「さらに」「加えて」
- 「つまり」「このように」「したがって」
- 「一方で」「その一方で」

#### 代替の自然な書き方

- 接続詞を**削る**(段落分けで処理する)
- 「ただし」「とはいえ」「ちなみに」「というのも」など人間らしい接続詞を使う
- 体言止めを混ぜる

#### Before

> 介護保険には1割負担と2割負担があります。また、所得に応じて3割負担になることもあります。さらに、高額介護サービス費制度を使えば自己負担を抑えられます。

#### After

> 介護保険の自己負担は基本的に1割。所得が一定以上だと2割、さらに高所得層は3割になります。
>
> 自己負担が重く感じる場合の救済策が、高額介護サービス費制度です。

「また」「さらに」を削るだけで、文の流れが格段に自然になる。

### 3.4 「具体的な誤解」を本文に入れる

YMYL記事で差がつくのが「**読者がよく抱く誤解**」を先回りして書くこと。
AIは無難に正解だけ書きがち。人間は読者の困りごとを知っている。

#### 例(相続税記事)

> 「うちは大した資産がないから相続税は関係ない」と思っている方が多いのですが、実は東京23区内に持ち家があるだけで基礎控除を超えるケースがあります。

「〜と思っている方が多い」のフレーズは、**実体験を装わずに人間味を出せる**便利な表現。

#### 例(終活記事)

> エンディングノートと聞くと「死ぬ準備」のイメージが強く、書き始めるのに抵抗を感じる方も少なくありません。実は、書き始めるタイミングは早い方がメリットが大きいと言われています。

### 3.5 専門用語の補足を「読者の頭の中の声」で書く

CLAUDE.md にも「専門用語には1行解説を併記」とあるが、これを**読者の心の声を代弁する形**で書く。

#### Before(AI臭い)

> 要介護認定は介護保険サービスを受けるために必要な認定です。

#### After(自然)

> 要介護認定とは、介護保険サービスを受けるための「等級づけ」のようなもの。要支援1〜2、要介護1〜5の7段階に分かれていて、数字が大きいほど重い状態を意味します。

「等級づけのようなもの」のような**例え**を入れることで、機械的でなくなる。

### 3.6 段落の冒頭をパターン化しない

AIは段落の書き出しが似がち:

- 「介護保険には〜があります」
- 「介護保険のポイントは〜です」
- 「介護保険を利用するには〜が必要です」

これを意識的に変える。

#### バリエーション例

- **体言止めで始める**: 「介護保険申請の流れ。まずは市区町村の窓口です」
- **問いかけで始める**: 「介護保険の申請、どこから始めればいいのでしょうか」
- **数字で始める**: 「3つのステップで、介護保険の申請は完了します」
- **状況描写で始める**: 「親の様子に変化を感じたとき、最初に検討するのが介護保険です」
- **対比で始める**: 「介護保険は便利な制度ですが、申請しなければ何も始まりません」

ひとつの記事の中で、これらの書き出しパターンを意識的に使い分ける。

### 3.7 「迷い」「ニュアンス」を残す

AIは断言しがち。人間は迷う。**断定を避けつつニュアンスを残す**のが上手な書き方。

#### 人間らしい表現

- 「〜と言われています」
- 「〜のケースが多いようです」
- 「一概には言えませんが、〜の傾向があります」
- 「自治体によって対応が異なるため、お住まいの地域の窓口で確認が必要です」
- 「〜が一般的とされていますが、ご家族の状況によって判断は変わります」

CLAUDE.mdの「断定を避ける」と完全に整合する。**そのまま使ってOK**。

## 4. 禁止表現と推奨表現の対照表

### 4.1 接続詞

| 禁止 | 推奨代替 |
|---|---|
| また | (削除して段落分け、または「とはいえ」) |
| さらに | (削除、または「加えて」「ちなみに」) |
| つまり | (削除、または「要するに」「言い換えると」) |
| このように | (削除、または「結果として」) |
| したがって | (削除、または「そのため」) |
| 一方で | 「ただし」「対照的に」 |
| 加えて | 「もうひとつ」「あわせて」 |

### 4.2 文末表現

| 禁止(断定的・AI臭い) | 推奨代替 |
|---|---|
| 〜です(連発) | 〜と言われています / 〜のことが多いです |
| 〜があります(連発) | 〜が用意されています / 〜という選択肢もあります |
| 必ず〜してください | 〜することをおすすめします / 〜が安心です |
| 絶対に〜 | 〜の傾向が強いです |
| 確実に〜できます | 〜できるケースが多いです |

### 4.3 開始フレーズ

| 禁止 | 推奨代替 |
|---|---|
| 〇〇とは、〜のことです | 〇〇は、簡単に言うと〜のような制度です |
| 〇〇には、以下の3つがあります | 〇〇のポイントは、大きく3つに分けられます |
| 〇〇を利用するためには、 | 〇〇を使い始めるとき、最初に必要なのが |

### 4.4 主語

| 禁止 | 推奨代替 |
|---|---|
| 私が(体験談禁止) | (主語を立てず一般化、または「ご家族の方」) |
| あなたは | 読者の方は / ご家族の状況によっては |
| みなさん | ご家族の方々 |
| 私たち | (削除、または「サイト運営者として」と限定) |

## 5. 感情表現の安全な使い方

### 5.1 OKな感情表現(状況描写・心情代弁)

- 「親の介護は、多くのご家族にとって悩ましい問題です」
- 「相続の話を切り出すのは、家族でも気が引けるものです」
- 「制度が複雑で戸惑う方も少なくありません」
- 「親が元気なうちにこそ、話しておきたいことがあります」
- 「いつかは向き合う必要があるテーマです」

### 5.2 NGな感情表現(体験談・押し付け・断定)

- ❌「私も親の介護で苦労しました」(体験談)
- ❌「本当につらいですよね」(共感の押し付け)
- ❌「絶対に後悔しない選択を!」(断定)
- ❌「これさえ知っておけば安心です」(誇大な印象操作)
- ❌「あなたなら大丈夫」(根拠のない励まし)

### 5.3 感情表現の使用頻度

1記事あたり**2〜3箇所**程度に抑える:

- 記事冒頭(リード文)で1箇所
- 記事中盤の難所(読者がつまずきやすいポイント)で1箇所
- 結論手前で1箇所

多用すると逆に「感情を操作している」印象になり、信頼性を損なう。

## 6. Q&A方式と体言止めの使い方

### 6.1 Q&A方式は「部分的に」使う

Q&A方式を全記事のメイン構造にすると、**逆にAI臭くなる**(ChatGPTでよく見るフォーマットのため)。

#### 推奨される使い方

- 記事全体の構造としては使わない
- 「**よくある誤解**」セクションで限定的に使う
- 1記事あたり3〜5個のQ&Aブロックまで

#### 例: 記事末尾の「よくある質問」セクション

```markdown
## よくある質問

**Q. 親が遠方に住んでいる場合、申請は誰がするのですか?**

A. 原則は本人または家族ですが、地域包括支援センターのケアマネージャーが代行することも可能です。離れて暮らす子どもが申請する場合、委任状が必要なケースがあります。

**Q. 申請してから認定が出るまで、介護サービスは使えませんか?**

A. 申請日にさかのぼって認定の効力が発生する仕組みなので、暫定的にサービスを利用することは可能です。ただし、認定結果によっては自己負担が増えるリスクもあるため、ケアマネージャーに相談することをおすすめします。
```

このセクションが3〜5個あると、検索エンジンが「FAQPage」構造化データとして拾いやすくなり、SEO上も有利。

### 6.2 体言止めは「リズムづくり」に使う

体言止めを混ぜると文体に変化が出るが、多用すると不自然。

#### 推奨される使用頻度

- 1段落あたり最大1箇所
- 記事全体で5〜10箇所程度
- 段落の最後に置くと締まりが出る

#### 例

> 介護保険の申請には、3つのステップがあります。
>
> まずは情報収集。市区町村の窓口で「介護保険を申請したい」と伝えると、必要書類のリストがもらえます。
>
> 次に申請書類の記入。本人または家族が記入しますが、わからない部分は窓口で聞けば教えてもらえます。
>
> 最後が認定調査の予約。これが終われば、あとは結果を待つだけです。

体言止め(「3つのステップ」「情報収集。」「記入。」「予約。」)が文章にリズムを生む。

## 7. カテゴリ別の書き出し例

各カテゴリで使える「**自然な書き出し**」のパターンを示す。

### 7.1 介護カテゴリの書き出し

```
親の様子に変化を感じたとき、最初に検討するのが介護保険です。

ただ、いざ調べ始めると、要支援・要介護・地域包括支援センター・ケアマネージャー...と、聞き慣れない言葉が次々に出てきて、どこから手をつければいいか分からなくなる方も少なくありません。

この記事では、介護保険の申請から認定までの流れを、必要な順番でまとめます。
```

### 7.2 相続カテゴリの書き出し

```
「うちは大した資産がないから、相続税は関係ない」

そう思っている方が多いのですが、東京23区内に持ち家があるだけで基礎控除を超えるケースが珍しくありません。

相続税の申告が必要かどうかは、まず「基礎控除額」を計算してみるのが第一歩。この記事では、計算方法と早見表を、できるだけシンプルに解説します。
```

### 7.3 終活カテゴリの書き出し

```
エンディングノート、と聞くと「死ぬ準備」のイメージが強くて、書き始めるのに抵抗を感じる方もいるかもしれません。

実は、エンディングノートは亡くなった後のためだけのものではないんです。書く過程で「自分が大切にしているもの」「家族に伝えたいこと」が整理されて、これからの生き方を見つめ直すきっかけになります。

何を書けばいいのか、どんな項目があるのか。今日はその基本を整理します。
```

### 7.4 お金カテゴリの書き出し

```
親の介護が始まったとき、家計に毎月どれくらいの負担がかかるのか。

「だいたい月10万円くらい」と聞いたことがある方もいるかもしれませんが、実際は介護度や住んでいる地域、自宅介護か施設かによって、月3万円から20万円以上まで大きく変わります。

この記事では、生命保険文化センターの最新調査をもとに、介護費用の月額目安と内訳を整理します。
```

## 8. 実践: 同じ内容のBefore/After比較

「介護保険申請の流れ」の冒頭を、AI臭い版と自然版で並べる。

### 8.1 AI臭い版(典型的なAI生成テキスト)

> 介護保険は、高齢者が必要な介護サービスを受けるための公的制度です。介護保険を利用するためには、市区町村に申請を行い、要介護認定を受ける必要があります。また、申請には介護保険被保険者証が必要です。さらに、認定結果が出るまでには約1ヶ月かかります。このように、介護保険の申請には複数のステップがあり、事前の準備が重要です。

問題点:
- すべての文が同じ長さ
- 「また」「さらに」「このように」が3連発
- 抽象的で具体性ゼロ
- 段落分けがない
- 「重要です」で締めるだけで、読者にとっての意味がない

### 8.2 自然版

> 親の介護が必要かもしれない、と感じたとき。最初に向かうのが市区町村の介護保険課です。
>
> ただ、いきなり窓口に行っても話が進まないことが多いです。まず必要なのが**要介護認定**を受けること。認定の数字によって、利用できるサービスや自己負担額が決まる仕組みです。
>
> 申請から認定結果が出るまで、目安は1ヶ月。意外と時間がかかります。「親が退院するから来週から介護サービスを使いたい」というケースには間に合わないこともあるため、早めに動き始めるのが現実的です。

改善点:
- 文長にリズム(短文「最初に向かうのが市区町村の介護保険課です。」+ 中文 + 長文)
- 「読者の状況」から書き始めている
- 「ただ」「意外と」など人間らしい接続詞
- 太字で重要語を強調
- 具体例(「親が退院するから来週から〜」)
- 体言止め(「最初に向かうのが市区町村の介護保険課です。」)

- [ ] 「具体的な誤解」を1箇所以上扱っているか
- [ ] 専門用語に「例え」を使った補足があるか

### 9.4 音読テスト

声に出して読んでみる(または音声合成で聞いてみる)。
**機械的に聞こえる箇所、引っかかる箇所、自然でない箇所がないか**を確認する。

引っかかった箇所は十中八九AI臭い。書き直す。

### 10.1 推奨プロンプト

```
docs/CLAUDE.md と docs/WRITING-STYLE.md を必ず読んでから、以下の記事を書いてください。

タイトル: 介護保険の申請から認定までの流れを解説

文字数: 2,500〜3,500字
hasAffiliate: false

【遵守すべきこと】

- 接続詞「また」「さらに」「つまり」「このように」は使わない
- 段落の書き出しを2種類以上のパターンで変える
- 文長にリズムをつける(短文・中文・長文の混在)
- 抽象的な記述には必ず数字・地名・年度のいずれかを添える
- 体言止めを3〜5箇所使う
- 「読者の心情を代弁する表現」を2〜3箇所入れる
- 「具体的な誤解」を扱うパラグラフを1つ作る

【出典】
厚生労働省「介護保険制度の概要」その他、公的資料3〜5本

【構成】
1. リード文(120字、読者の状況から書き始める)
2. 結論先出し(3〜5行で要点)
3. 申請の流れ(5ステップ)
4. よくある誤解(Q&A形式で2〜3個)
```

### 10.2 生成後の人間チェック

Claude Code が生成した記事は、必ず人間が読んで以下を確認:

- 音読して引っかかる箇所がないか
- 全体のリズム感が機械的になっていないか
- 専門用語の例えが適切か(極端に俗っぽくなっていないか)
- 出典が実際にその内容を書いているか(ハルシネーション確認)

人間の手で2〜3割を書き直すつもりで臨む。完全自動化は推奨しない。

## 11. 参考: AIコンテンツ検出ツールでの自己チェック

4. 具体例(数字・地名)を増やす

## 12. まとめ: 記事品質の3層構造

実家のしらべの記事は、以下の3層を全て満たして初めて「価値ある記事」になる:

### 12.1 Layer 1: 法令遵守(絶対要件)

- CLAUDE.md セクション1.4 の方針を100%守る
- 体験談禁止、断定禁止、出典必須
- 個別助言をしない

### 12.2 Layer 2: 情報の正確性(YMYL要件)

- 公的資料を一次情報として引用
- 数字・年度・出典を明示
- 制度改正の可能性に触れる

### 12.3 Layer 3: 文体の自然さ(本ガイドの範囲)

- AI臭い接続詞・構造を避ける
- リズムと具体性のある文章
- 読者の状況・心情に寄り添う

3層全てが揃って、はじめて「介護当事者として読みたくなる、Googleにも評価される、ASPからも信頼される記事」になる。
