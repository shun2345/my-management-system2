## コンフリクト発生リスク

同じファイルを変更するイシューの組み合わせ。**同時に別ブランチで作業すると merge conflict が起きやすい**。

| ファイル | 関連イシュー | リスク | 対策 |
|---------|-------------|:------:|------|
| `lib/seo.ts` | #12, #27, #30 | **高** | #12 → #30 → #27 の順で直列に処理 |
| `lib/jsonld.ts` | #13, #27 | **高** | #13 → #27 の順で直列に処理 |
| `app/sitemap.ts` | #15, #27 | **高** | #15 → #27 の順で直列に処理（#27 は全ハードコード箇所を一括修正） |
| `app/robots.ts` | #15, #27 | **高** | 同上 |
| `app/layout.tsx` | #5, #12, #21 | **中** | #5 が先行。#12 は `generateMetadata` で分離可能。#21 は末尾にスクリプト追加のみ |
| `app/globals.css` | #5, #29 | **中** | #5 が先行。#29 はダークモード変数追加のため影響範囲は限定的 |
| `components/mdx/Callout.tsx` | #10, #29 | **高** | #10 → #29 の順で直列に処理（#29 は #10 で作ったものを修正） |
| `components/mdx/AffiliateCard.tsx` | #11, #28 | **高** | #11 → #28 の順で直列に処理（#28 は #11 で作ったものを修正） |

| `scripts/check-citations.ts` | #20, #26 | **高** | #20 → #26 の順で直列に処理 |

## 推奨事項

1. **#27（env変数集約）は #12, #13, #15 の全完了後にまとめて着手する**。複数ファイルを横断するため、先行イシューが全て main にマージされた状態で行うのが最もコンフリクトリスクが低い。

2. **バグ修正イシュー（#25〜#30）は、対象の本体イシューと同一ブランチで一緒に修正してもよい**。例えば #10 のブランチで #29 のダークモード修正も含めると、別 PR を切る手間とコンフリクトリスクを両方減らせる。ただし 1 イシュー = 1 PR のルールとの兼ね合いで判断すること。

3. **#16（Affiliate管理）は依存なしなので、Step 2〜3 の間に前倒しで着手可能**。早めに作っておくと #11 への着手がスムーズになる。

4. **#22（Vercel デプロイ）は全体の最後だが、Preview デプロイだけは早期に設定しておくと各 PR のレビューが楽になる**。Vercel プロジェクト連携だけ先に行い、本番ドメイン設定は最後にする方法も検討。
