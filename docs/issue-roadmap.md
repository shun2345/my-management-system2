## コンフリクト発生リスク

同じファイルを変更するイシューの組み合わせ。**同時に別ブランチで作業すると merge conflict が起きやすい**。

| ファイル | 関連イシュー | リスク | 対策 |
|---------|-------------|:------:|------|
| `components/mdx/AffiliateCard.tsx` | #11, #28 | **高** | #11 → #28 の順で直列に処理（#28 は #11 で作ったものを修正） |
| `scripts/new-post.ts` | #19, #26 | **高** | #19 → #26 の順で直列に処理 |
| `scripts/check-citations.ts` | #20, #26 | **高** | #20 → #26 の順で直列に処理 |
| `package.json` | #19, #20, #26 | **中** | scripts セクションへの追記が多い。マージ順を意識する |
| `app/api/og/route.tsx` | #14, #25 | **中** | #14 → #25 の順 |

## 推奨事項

1. **Step 1〜3 の大半が即時着手可能になっている**。#13, #14, #15, #16, #17, #18, #19, #20, #21, #29 は依存先がすべて完了しており、並行して進められる。

2. **バグ修正イシュー（#25, #26, #28）は対象の本体イシューと同一ブランチで一緒に修正してもよい**。例えば #11 のブランチで #28 のガード節も含めると、別 PR を切る手間とコンフリクトリスクを両方減らせる。ただし 1 イシュー = 1 PR のルールとの兼ね合いで判断すること。

3. **#16（Affiliate管理）→ #11（PRBadge/AffiliateCard/ExpertCTA）の順序は厳守**。#11 の AffiliateCard が lib/affiliate.ts に依存するため。

4. **#22（Vercel デプロイ）は全体の最後だが、Preview デプロイだけは早期に設定しておくと各 PR のレビューが楽になる**。Vercel プロジェクト連携だけ先に行い、本番ドメイン設定は最後にする方法も検討。

5. **#29（Callout テーマ修正）は即時着手可能**。#10 が完了しているため、優先度に応じて早めに対応できる。
